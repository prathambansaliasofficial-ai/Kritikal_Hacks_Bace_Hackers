## T4.1 — Wallet user + KYC stub

`backend/db/005_users.sql`:

```sql
users(id BIGSERIAL PK, wallet_address TEXT UNIQUE NOT NULL,
      role TEXT CHECK (role IN ('CITIZEN','OFFICER')) DEFAULT 'CITIZEN',
      kyc_status TEXT CHECK (kyc_status IN ('PENDING','VERIFIED','REJECTED')) DEFAULT 'PENDING',
      created_at, updated_at)
```

Routes: `POST /api/v1/users` upsert by wallet; `GET /api/v1/users/{wallet}`;
`POST /api/v1/users/{wallet}/kyc` with `X-Officer-Token` matching `DEV_OFFICER_TOKEN`.
Validate wallet with `^0x[a-fA-F0-9]{40}$`. Add `DEV_OFFICER_TOKEN` to `backend/.env.example`.

Tests: invalid wallet 422, missing/bad token 401, KYC update 200.

## T4.3 — Order lifecycle

Use existing `orders` table; add columns only if missing (the schema already has `chain_order`,
`tx_hash`, `evidence_hash`). Routes per contract. Rules:

- buyer exists/KYC `VERIFIED`; listing `LISTED`; buyer ≠ seller; amount = listing price;
- `POST /orders` inserts `CREATED` and copies seller/amount;
- `POST /orders/{id}/funded` accepts `chain_order_id` + `tx_hash`, validates bytes32,
  recomputes `chain_order_id` (decisions §5), transitions `CREATED→FUNDED`; duplicate 409;
- `GET /orders/{id}` returns the order shape.

Tests: self-buy 409, unverified 409, wrong amount 409, duplicate funding 409, happy path.
